## Cron infra fix (13:45 UTC) — model idle timeout
- Watchlist Daily Price Check (9 AM ET) failed 7 weekdays straight: "model idle timeout" (DeepSeek slow to respond; default ~120s idle watchdog too tight). Failure notifications also weren't delivering (lastFailureNotificationDelivered: false) — surfaced only today.
- EPL daily agent had the same error 8x; Weekly Portfolio Check-In 2x. Same root cause.
- **Fix applied:** `models.providers.deepseek.timeoutSeconds: 300` + `agents.defaults.timeoutSeconds: 600` via `openclaw config patch` — hot-applied, no gateway restart.
- Verified: manual `openclaw cron run` of the watchlist check → status ok, report delivered to Telegram.
- Lesson: any cron whose job is a *multi-step agent turn* can hit the idle watchdog on slow API days; check `openclaw cron list` for `error (Nx)` — the count is the tell. Don't rely on failure notifications; they can fail too.
