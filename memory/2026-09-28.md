## ADR currency bug in the Quality-on-Discount screener — FIXED
Kofi (01:35 UTC): "NVO's screen score is meaningless; fix the currency bug before that
screener runs again, because it will misfire on every ADR with non-USD fundamentals."

### Root cause (verified against live Yahoo, not guessed)
`opportunity.py::fetch_fundamentals` pulled `financialData` statement figures without
checking `financialCurrency`. Prices/market cap arrive in the **quote** currency (USD),
statement money values arrive in the **financial** currency (DKK for NVO, CAD for CCJ).
Blended → junk:
- NVO FCFy 29.1% = FCF DKK 37.67B ÷ USD market cap (DKK treated as USD)
- NVO EV/EBITDA 1.5 = Yahoo's own `enterpriseValue` is blended too:
  171.4 (USD mkt cap) + 140.1 (DKK debt) − 45.0 (DKK cash) = 266.5 → the 267.0B it reports.
  So even Yahoo's `enterpriseToEbitda` / `enterpriseToRevenue` are garbage for ADRs.
- ROIC~76% came from the same unit salad (DKK debt vs USD-ish equity base).
`trailingEps` + `bookValue` DO come back in quote currency (verified: priceToBook
5.10 = 38.80 ÷ 7.60284) so EY/ROE/margins were never affected — only the money legs.

### Fix (opportunity.py, cache version bumped to v2)
1. New `fx_rate(fin_ccy, quote_ccy)` — Yahoo chart meta on `<FIN><QUOTE>=X`, direct pair
   then inverse, sanity-checks the quote leg; cached per process. DKK→USD = 0.1523.
2. Fetch `price` module too; read `price.currency` + `financialCurrency`.
3. Convert FCF/OCF/debt/cash/EBITDA/revenue into quote currency; `market_cap` now prefers
   `price.marketCap` (NVO dual-class: 171.4B real vs 129.7B from ADR-count × price).
4. For mismatched names rebuild EV = mkt cap + debt − cash and EV/EBITDA ourselves.
5. Revenue proxy = EBITDA ÷ ebitdaMargins (units cancel) instead of EV ÷ EV-to-rev.
6. **Fail closed:** no FX rate → money fields None (nothing scores) + `fx_failed` marked,
   and the cache entry is retried next run.
7. `VALUE_CACHE_VERSION = 2` invalidates the stale garbage cache — critical, otherwise
   the 7-day cache would have kept feeding NVO's bad numbers into Saturday's run.
8. Report line now prints `ccy=DKK` so a normalized row is visible.
