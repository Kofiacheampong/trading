## BUG FIX — "Budget watchlist dip alerts" cron was firing garbage daily
- **Symptom:** 9:40 AM ET alert said "4 of 5 triggered", LULU "−17.1% below Friday", KMB "−11.3%". Basket was actually flat (LULU $98.14 +0.09%, KMB $96.87 −1.01%, ZTS $70.80 −0.94%, PYPL $52.48 +0.14%).
- **Root cause:** the cron prompt hardcoded "Friday Jul 31" baselines (LULU 118.87, KMB 109.31, ZTS 77.29, PYPL 57.21, PAYC 163.96) + **absolute** thresholds (LULU<112, KMB<103, ZTS<73, PYPL<53, PAYC<152). By Sept every name except PAYC sat permanently below its threshold → could never un-trigger, fired every weekday, and the "% below" was computed vs a 7-week-old price.
- **Fix:** new deterministic script `scripts/budget_dips.py` (no LLM price-fetching, no improvising):
  - dip zone = price ≤ 95% of 20-day SMA (self-normalising, can't get permanently stuck)
  - fresh dip = day ≤ −3.0%, **or** new 20-day low while in zone on a ≤−1.5% day
  - one alert per ticker per calendar day (state: `scripts/.budget_dips_state.json`)
  - refuses to alert if the latest bar is >4 days old
  - prints `NO_REPLY` when nothing triggers → cron stays silent
- Cron payload (`061e8204`) rewritten to just run the script and relay/NO_REPLY. Tested with `openclaw cron run`: status ok, summary NO_REPLY, **delivered: false** ✓.
