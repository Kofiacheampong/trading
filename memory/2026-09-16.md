# 2026-09-16

## 🚨 "Hallucination" audit — betting-agent phantom voids (Kofi: "this shit hallucinationg again?")

Kofi was reacting to the 14:05 UTC CL cron message (#2879) voiding 4 bets as "no result — refunded".

**Verdict: not a model hallucination — the FIXTURES WERE REAL AND WERE PLAYED.** Verified against
UEFA.com official 2026/27 league-phase fixtures & results page (MD1, Sep 8–10 2026):

- Liverpool **2-1** Atlético de Madrid (match 2049560) → our h2h_away bet **LOST** −0.52u
- Sporting CP **3-1** Galatasaray (2049562) → our h2h_home bet **WON** +0.40u
- Paris Saint-Germain **6-1** Slovan Bratislava (2049559) → both bets **LOST** −1.91u / −1.25u
- Same bug in EPL book: Chelsea **4-3** Brighton (Aug 30, ESPN gameId 401879317) voided as "no result"
  → the h2h_draw bet actually **LOST** −2.00u

**Root cause (two layers):**
1. `step.py` / `cl_step.py` settled bets by matching **team names**; when the scores feed's `scores[]`
   names didn't resolve, both score lookups returned None and the loop did a bare `continue` —
   a **silent skip**. No warning, no log, nothing.
2. `_void_stale_open_bets` then auto-refunded those bets after 5 days as "no result" — again silently.
   Compounding: the Odds API scores endpoint only looks back **3 days** (free tier: `daysFrom` >3 →
   INVALID_SCORES_DAYS_FROM), and the CL cron only runs **Tue/Wed/Thu** — the Thu→Tue gap is 5 days,
   so anything the Thu run misses ages out of the window permanently. Observed: the Sep 10 run settled
   the 16:45 UTC Wed fixtures but NOT the 19:00 UTC ones → those 4 bets were doomed.

**Damage:** both paper books were **inflated by +5.28u of fake refunds** (CL −3.28u, EPL −2.00u) — in the
*flattering* direction, feeding the gate metrics that decide whether real money goes in.

**Fix applied:**
- Books corrected: CL bankroll 88.39 → **85.11**; EPL 109.50 → **107.50**. Backups:
  `betting/book_cl.json.bak-20260916`, `betting/book.json.bak-20260916`. Corrections logged in each
  file (`corrections[]` + per-bet `note`/`corrected` with sources).
- Settle now matches by **event_id first** (immune to name drift), name second.
- Unresolvable completed fixture + open bet → loud **WARN** (never a silent skip).
- New `_flag_unresolved()`: every missing result is surfaced **on the first run after kickoff**.
- Voids are labelled **UNVERIFIED** with an instruction to confirm the fixture wasn't played.
- Regression-tested: accented-name payload (the real Sep 9 case) now settles; unreadable payload warns.

**Second finding — the CL lane's CLV was always 0.00%:** two causes, only one of which was cadence.
(A) **`cl_step.py` never called `update_closing()` at all** — closing odds on all 13 CL bets still
    equal entry odds. The EPL lane calls it (`step.py:223`); the CL copy was missing it. **This was the
    real bug** — I first blamed the Tue/Wed/Thu cadence, which was wrong; Kofi pushed back on the daily-run
    proposal and was right. Fixed by importing + calling `update_closing(bk, fixtures)`.
(B) The 3-day scores lookback vs the Thu→Tue run gap means **Thursday-slate CL fixtures are
    structurally unsettleable** (Thu run happens before Thu kickoff; next run Tue is 5 days out → result
    ages out → silent void). Fixed WITHOUT touching the schedule: new `RUN_DAYS`/`_settleable()` guard in
    `cl_step.py` refuses to open bets whose result the next run can't catch, and prints a `SKIP would-void`
    line so it's visible. If we ever want Thursday-slate CL bets, the cheap option is +Fri on the CL job
    (~8 API calls/month), not a daily run.

**Lane status after correction:** 13 settled, 15% win rate, −14.9u, ROI −89.5%. The cross-league
Poisson overconfidence I flagged on Sep 8 is confirmed. Nowhere near real money.
